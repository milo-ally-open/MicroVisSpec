# 推送调试工具合同

2026-10-22；用户授权独立调试表单和逻辑后端，初次交付保留本地改动；用户随后授权复查通过后提交至 dev。

## 目标与边界

在显式配置的测试账号下创建独立模拟设备，通过现有激活、配置、MQTT 事件、事件 outbox、Push inbox 和 PWA 通知链路验证推送。不新增生产服务路由，不直写业务数据库，不替真实 Atlas 推理验收。地点来自模拟设备主数据；只支持 event-service 当前接受的举手、阅读、书写事件。测试账号所有有效订阅是接收范围。

## 需求与验收

- REQ-01 / AC-01.1：静态表单可选测试账号、事件类型、地点、时间和等级，点击后返回可访问的真实事件 ID；页面和设备明确标记模拟数据。
- REQ-01 / AC-01.2：不接受任意账号 ID、设备凭据或未支持类型；每个配置账号独立登录、独立模拟设备和 MQTT 身份，账号 B 不能访问账号 A 的事件。
- REQ-02 / AC-02.1：模拟端先接收规则并 ACK，再产生满足规则的事件；同一请求 ID 重试复用同一事件，页面轮询不重发事件。
- REQ-02 / AC-02.2：区分设备 ACK、事件查询可见、Push 服务受理、provider accepted 与浏览器实际显示。无订阅不声称成功通知；页面不泄漏 endpoint、密码、私钥和订阅密钥。
- REQ-02 / AC-02.3：首次 MQTT 连接失败后允许后续请求重新连接；可选证据失败不丢失已创建事件的 ID/详情地址，不因此重复发布事件；证据处理期间继续轮询，结束后准确显示上传结果。
- REQ-03 / AC-03.1：服务只绑定 127.0.0.1，校验 Host/Origin 与随机 CSRF token；凭据和运行状态保存在 Git 忽略的配置目录；仅允许已配置 profile。
- REQ-03 / AC-03.2：可选只读观察器读取 outbox/delivery 状态；不提供数据库或通用命令执行接口。未配置观察器时如实显示未观察。
- REQ-04 / AC-04.1：支持 HTTPS PWA 上真实订阅、通知显示与点击回跳验收；真实浏览器或手机未执行时记录待验收，不以 fake sender 或 CDP 合成消息代替。

## 设计

Python 标准库 HTTP 服务承载 index.html，requests 管理每个 profile 的服务端 Cookie/CSRF，paho-mqtt 管理模拟设备。服务端串行化单个 profile 的规则、地点与事件生成，避免互相覆盖。每次请求有稳定 request_id/edge_event_id；进程内去重，持久保存任务的最小安全状态供重启恢复查询，重启后不自动重发未确认任务。只读 observer 是服务器配置的固定 Docker PostgreSQL 容器与数据库，使用严格解析的 UUID 构造固定查询，不接收浏览器提供的 SQL/命令。数据库观察通过事务 READ ONLY，返回 allowlist 状态与计数。

时间处理：默认 `occurred_at=now`，在规则配置被 ACK 后生成真实当前时间；自定义时间保留平台的规则历史准入，早于规则生效的事件会被正式服务拒绝，不绕过校验。规则未改变时复用已应用版本，减少无意义配置变更。

本工具是本机联调工具，配置账号需要由操作者明确提供，不枚举生产用户。故不改变生产账号授权或事件服务合同。关闭工具即可停止模拟心跳；生产数据和卷不执行删除。
