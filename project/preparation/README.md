# 单模型标准研发流程

每个场景独立放在一个 `model_<scenario>/` 目录中。训练脚本、转换产物、评估报告和板端 Demo 不跨模型共用目录；复制既有代码时也要保留场景自己的可执行版本和记录。

## 固定阶段

| 目录 | 工作范围 | 主要交付 |
|---|---|---|
| `01_model_train/` | 固定数据来源与版本，下载、检查、分析和划分数据；训练 YOLO 并在留出集验证 | 数据说明、训练参数与种子、权重、训练和验证报告 |
| `02_model_convert/` | 从权重导出固定输入 ONNX；需要剪枝时记录剪枝前后配置与指标；用目标 Atlas 板卡的 ATC 转换 OM | ONNX、OM、导出/转换清单、工具版本和 SHA-256 |
| `03_model_val/` | 用相同测试集和预处理对 ONNX 与 OM 做精度对比；ONNX 有可用 GPU 时优先 GPU；分开记录总体和逐类别指标、性能及内存 | 精度/性能/内存评估脚本、对比报告、设备实测记录 |
| `04_model_demo/` | 交付最小板端视频推理工程，验证视频输入、NPU 推理、后处理和视频输出 | C/C++ 源码、构建配置、模型类别表、使用说明和演示验收记录 |

## 运行顺序与产物交接

1. 先完成 `01_model_train/` 的数据准入和训练验证。训练验证结果不替代独立测试集评估。
2. `02_model_convert/` 读取已确认的 checkpoint，保存可复算的 ONNX 和 Atlas OM；清单记录输入/输出哈希和实际工具链版本。
3. `03_model_val/` 对同一测试集运行 ONNX 与 OM 评估。图像尺寸、类别顺序、阈值与预处理必须一致；设备推理结果标明板卡型号与 CANN 版本。没有设备数据时写明未测，不用桌面数字代替。
4. `04_model_demo/` 使用 `02_model_convert/` 的 OM 和相同类别配置，运行真实视频文件或实时视频源，并记录输出、帧数、时延及设备资源。

各模型根目录保留自己的 `WORKFLOW.md` 或任务总说明，链接到这四个阶段。阶段间通过有哈希的文件交接；不要把两个模型塞进同一训练、转换、评估或 Demo 工作目录。
