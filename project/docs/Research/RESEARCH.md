# 前后端联调演示版：范围与现状调研

> 状态：初稿；用于支持 PRD 0.5 的待确认提案
> 调研日期：2026-10-03

## 调研问题与决策

判断当前项目是否适合在不依赖摄像头和实时算法的情况下，开展一个最小前后端联调阶段；明确需要保留的边界和未决技术问题。

本调研基于仓库现状，不对后端框架、数据库或部署环境作最终选型。

## 范围与方法

- 阅读根目录 README、PRD、项目工作流和 `project-docset` 的文档边界说明。
- 检查浏览器告警原型及 `project/src/services/` 服务目录。
- 检查当前本机模型实验报告和 Git 跟踪状态，区分本地实验资产与仓库共享资产。
- 纳入用户提供的团队分工说明与聊天截图。
- 未进行外部技术方案或产品市场调研；具体选型留待团队确认范围后开展。

## 证据与发现

| 仓库证据 | 观察 | 对下一阶段的含义 |
|---|---|---|
| [README.md](../../../README.md) | 描述长期目标：边缘识别、云端事件汇聚、监控与移动端告警、数据分析和 MCP。 | README 是整体愿景，不等于当前都要实现。 |
| [PRD.md](../Analysis/PRD.md) | 当前原型限定为模拟告警；0.4 增加单点位全栈联调提案，尚待团队确认。 | 先确认范围，再选技术和写实现任务。 |
| 本机工作区 `project/src/clients/web/alert-prototype/` | 事件由页面生成并保存在当前浏览器的 `localStorage`，没有 API 或服务端存储；原型代码不包含在本次文档交接中。 | 可复用现有列表、详情和状态流转；共享分支需另行提交原型后才能查看，数据源可在未来替换为后端 API。 |
| `project/src/services/` | device-service、media-service、user-service、mcp-service 目前只有占位文件。 | 当前没有既有服务接口或服务实现需要兼容。 |
| 本机 `video/datasets/fire_lane_monitor/training_runs/` 实验报告 | 存在 YOLO 分割基线和静态图片实验；模型未集成实时流、占用持续时间判定或告警 API。 | 可将真实算法事件作为未来输入；全栈模拟阶段无需等待模型。 |
| 本机 `.git/info/exclude` 对 `video/datasets/` 的忽略规则 | 权重和数据不由 Git 自动分享，实验报告也属于本机数据目录。用户明确要求模型权重不得上传代码仓库。 | 权重不能提交或推送到代码仓库；不能把本地模型当成远端仓库已经交付的功能。若需共享，另行使用仓库外方式并先确认。 |
| 用户提供的团队分工截图与说明 | 队友负责图片/算法相关工作；用户负责其他项目工作。截图所列模型范围包括数据准备、模型设计训练、评估、转换和部署推理。 | 平台前后端、告警服务和模型输出接入由用户负责；模型推理结果如何交给平台需要双方约定接口。 |

## 结论与建议

1. 推荐把下一阶段作为独立的“前后端联调演示版”提案，而不是把 README 中所有长期能力都纳入当前交付。
2. 提案仅覆盖单点位、模拟事件、后端持久化和网页通过接口读取/更新状态。
3. 先用模拟事件生产者验证接口；真实 YOLO 或边缘设备之后通过同一事件输入边界接入。
4. 演示规模下建议先研究单体后端和一种持久化存储，不提前拆分多个微服务。最终选择需比较团队熟悉度、部署环境、成本与维护复杂度，并记入 SPEC。
5. 前端现有 `localStorage` 逻辑是单浏览器演示存储，不构成跨设备数据服务。

## 对 PRD、Design 与 SPEC 的影响

- PRD：保留当前原型基线，将全栈联调版显式标为待确认提案。
- Design：描述浏览器、模拟事件入口、告警 API 与持久化边界；真实模型入口标为未来集成。
- SPEC：给出候选 API 和事件数据模型供讨论，技术栈、数据库和算法字段仍需确认。

## 局限与待确认

- 团队责任分工已由用户说明；全栈联调阶段是否获团队批准仍待确认。
- 目标部署系统、允许使用的后端技术、数据库约束和共同开发环境未在仓库说明。
- 本机模型的训练者、团队共享状态及模型许可需队友确认；任何权重共享都必须在代码仓库以外进行。
- 本调研没有测量服务吞吐、可用性或安全需求，不支持生产部署结论。
