# 消防通道占用告警平台 PRD

> 状态：初稿待审阅；0.4 版新增“前后端联调演示版”提案，0.5 版补充团队分工；范围待团队确认
> 版本：0.5
> 最近更新：2026-10-03

## 背景问题

园区、工厂等场所需要发现消防通道占用，并让值班人员及时查看事件、联系现场处置人员和跟进处理结果。项目 README 将消防通道占用检测列为首发场景，目标是验证从异常发现到处置反馈的业务闭环。

当前没有可接入的摄像头或实时视频。项目本机已有一个基于公开数据训练的 YOLO 分割基线，可对静态图片尝试识别车辆和消防通道区域；它尚未接入视频流，也没有稳定的占用判断、持续时长判断和告警上报链路。模型文件目前仅在本机，未纳入 Git，团队共享状态和训练者待确认。

## 当前原型

本机工作区已有浏览器原型 `project/src/clients/web/alert-prototype/`，目前只演示一个模拟点位；可通过页面生成模拟告警，在列表和详情中查看，并更新处置状态。事件存储在当前浏览器的 `localStorage`，不连接后端、摄像头或算法。示意画面和事件明确标记为模拟内容。该原型代码不包含在本次文档交接中，需另行提交后队友才能从仓库查看。

## 用户画像

- **主要用户：园区或工厂值班人员**，例如安保值班员或消防管理人员，负责查看告警、联系现场人员并跟进结果。
- **协作角色：现场处置人员**，按值班人员通知前往现场，反馈处理进度和结果。
- **管理人员：**可能需要查看重复事件和分布情况，属于后续分析需求，本阶段不覆盖。

## 场景

值班人员收到消防通道占用告警后，查看发生时间、点位和现场截图，联系现场人员核实并处置，再将事件标记为“处理中”“已解除”或“误报”。当前原型中的事件为手动生成的模拟数据。

**下一阶段提案（待团队确认）：**演示者通过页面生成一条模拟事件；后端保存事件并返回记录；网页从后端读取告警列表和详情，并提交处置状态更新。不同浏览器连接同一个后端时应看到相同记录。该流程仍不表示真实算法识别结果。

## 用户故事

- 作为园区或工厂值班人员，我希望查看告警的时间、地点和现场截图，以便判断需要关注的事件。
- 作为园区或工厂值班人员，我希望记录事件正在处理、已解除或属于误报，以便跟进处置结果。
- 作为下一阶段演示者，我希望模拟告警能保存到后端并由网页读取，以便演示前后端联调流程。**此故事属于待团队确认的阶段提案。**
- 作为现场处置人员，我希望收到值班人员提供的事件地点和情况，以便前往现场处理并反馈结果。当前版本不包含通知送达功能；现场人员如何获得并反馈信息仍待确认。

## 功能范围

### 当前 MVP：模拟告警处置原型

- 通过页面操作生成模拟消防通道占用告警。
- 只演示一个模拟点位。
- 在告警列表中查看事件，并打开详情。
- 详情显示发生时间、点位和模拟截图；模拟内容需明确标注，避免被误认为真实检测结果。
- 值班人员可将事件更新为“处理中”“已解除”或“误报”。
- 模拟告警在当前浏览器刷新或重新打开后仍可查看。

### 下一阶段提案：前后端联调演示版（待团队确认）

- 保留单点位和模拟事件，不依赖摄像头或模型推理。
- 页面生成的模拟事件通过后端接口保存；告警列表、详情和状态更新由前后端接口完成。
- 事件在同一后端服务的多个浏览器会话间共享，并在刷新后保留。
- 继续明确展示“模拟数据”标识；沿用静态示例截图，不要求真实图片上传。
- 先采用单一后端应用和一种持久化存储；具体技术选型在 Research 与 SPEC 阶段确定。

### 后续迭代候选

- 接入真实 YOLO 推理结果，并实现车辆与消防通道区域关系、持续占用时长判断。
- 接入 RTSP 视频和边缘设备，验证端到端检测效果。
- 管理多个真实设备和点位。
- 将告警推送至 PWA 或手机客户端。
- 提供事件统计分析大屏及 MCP 服务。

### 当前阶段及提案不做

- 真实视频接入、实时画面播放、边缘硬件部署和真实自动告警。
- 宣称或验收真实识别准确率、误报率和现场告警时延。
- 手机推送、现场人员账号与任务派发、完整用户权限。
- 多租户、多点位管理、数据分析大屏和 MCP Agent 集成。
- 为当前前后端联调演示版建设独立微服务集群或通用媒体上传平台。

## 成功指标

- **当前原型验收标准：**演示者可以生成模拟告警、查看时间/点位/截图，并将其更新为“已解除”或“误报”。
- **下一阶段提案验收标准（待确认）：**模拟事件成功写入后端；刷新页面或使用另一浏览器连接同一后端后仍能查看；状态更新后再次读取仍显示新状态；模拟数据始终有清晰标识。
- 真实识别效果需在获得合适视频和检测链路后另行制定指标。

## 约束与假设

- [已确认] 当前没有可用的摄像头或实时视频接入条件。
- [已确认] 浏览器原型使用模拟事件和静态示例图，不能代表真实识别结果。
- [本机现状] 已有 YOLO 分割基线可对静态图片推理；它未集成到应用，当前不能产生可靠的实时占用告警。
- [本机现状/约束] 模型权重被本机 Git exclude 规则忽略；不得将权重文件加入、提交或推送到代码仓库。其他队员能否取得相同权重、其来源及训练者待确认。
- [待团队确认] 是否将前后端联调演示版作为下一阶段交付范围。
- [待确认] 后端技术、存储方案及算法侧将来提交事件的字段，在需求范围确认后通过调研和技术规格确定。

## 风险与依赖

- 本阶段的模拟数据只能验证交互、持久化和接口联调，无法验证算法、视频接入或现场使用效果。
- [用户确认的分工] 队友负责图片/算法链路，包括数据集准备、模型训练评估和部署推理；用户负责其余项目工作，包括平台前后端和系统集成。模型输出如何交给平台仍需双方约定。
- 算法与平台需要约定事件数据和截图引用方式；实际字段仍待技术规格确定。
- 模型权重不得上传到代码仓库；Git 当前不会自动同步本机权重。若团队以后确需共享权重，需另行确认仓库外的存储和访问方式。
- 获得测试视频或摄像头后，需单独校准占用判断和持续时长，不能直接沿用静态图片实验结果。
