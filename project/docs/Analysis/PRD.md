# 消防通道占用告警模拟版 PRD

> 状态：初稿待审阅  
> 版本：0.2  
> 最近更新：2026-10-02

## 背景问题

园区、工厂等场所需要发现消防通道占用，并让值班人员及时查看事件、联系现场处置人员和跟进处理结果。项目 README 将消防通道占用检测列为首发场景，目标是验证从异常发现到处置反馈的业务闭环。

当前无法接触摄像头，也没有可运行的检测算法。因此，本阶段先用模拟告警讨论和演示告警处置流程；这不能验证真实视频识别能力或现场部署效果。

## 用户画像

- **主要用户：园区或工厂值班人员**，例如安保值班员或消防管理人员，负责查看告警、联系现场人员并跟进结果。
- **协作角色：现场处置人员**，按值班人员通知前往现场，反馈处理进度和结果。
- **管理人员：**可能需要查看重复事件和分布情况，属于后续分析需求，本版不覆盖。

## 场景

值班人员在模拟版中点击“生成模拟告警”，看到一条标明为模拟数据的消防通道占用事件。值班人员打开详情查看发生时间、点位和模拟截图，联系现场人员后更新事件状态；收到现场反馈后，将事件标记为“已解除”，也可以将误报标记为“误报”。

## 用户故事

- 作为园区或工厂值班人员，我希望查看消防通道占用告警的时间、地点和现场截图，以便判断需要关注的事件。
- 作为园区或工厂值班人员，我希望记录事件正在处理、已解除或属于误报，以便跟进处置结果。
- 作为现场处置人员，我希望收到值班人员提供的事件地点和情况，以便前往现场处理并反馈结果。**本版不包含通知送达功能**；现场人员如何获得并反馈信息仍待确认。

## 功能范围

### MVP：模拟告警处置原型

- 通过页面操作生成一条模拟消防通道占用告警。
- 首版只演示一个模拟点位。
- 在告警列表中查看事件，并打开详情。
- 详情显示发生时间、点位和模拟截图；模拟内容需明确标注，避免被误认为真实检测结果。
- 值班人员可将事件更新为“处理中”“已解除”或“误报”。
- 模拟告警在刷新页面或重新打开原型后仍可查看。

### 后续迭代候选

- 接入真实摄像头和可运行的检测算法，验证识别效果。
- 将告警推送至 PWA 或手机客户端。
- 管理多个真实设备和点位。
- 提供事件统计分析大屏及 MCP 服务。

### 本版不做

- 真实视频接入、实时画面播放和计算机视觉识别。
- 识别准确率、误报率、告警时延等真实算法指标验证。
- 手机推送、现场人员账号与任务派发。
- 数据分析大屏和 MCP Agent 集成。

## 成功指标

- **已确认的原型验收标准：**演示者可以生成模拟告警、查看时间/点位/截图，并成功将其更新为“已解除”或“误报”。
- 模拟数据与真实告警清晰区分。
- 真实识别效果暂不设指标；获得可用视频和检测算法后再定义。

## 约束与假设

- [已确认] 当前无法接触摄像头，且没有可运行的检测算法。
- [已确认] 本阶段使用模拟事件，不以模拟结果代表真实识别效果。
- [已确认] 模拟告警在刷新页面或重新打开原型后保留。
- [已确认] 首个原型只演示一个模拟点位。
- README 描述团队算法可部署于国产芯片，并计划以 RK3588 验证首发场景；结合当前状态，本 PRD 将其视为未来目标，部署可行性尚未验证。

## 风险与依赖

- 模拟数据只能验证界面和处置流程，无法验证算法、摄像头接入或现场使用效果。
- 进入真实识别验证前，需要获得测试视频或摄像头访问条件，并形成可运行的检测算法。
- 模拟截图需要清楚标记为示例内容；在获得合适素材前可使用占位图。

## 待确认

- 当前没有阻塞 PRD 初稿审阅的需求决定。真实算法的识别对象、判定阈值和验证指标需在获得可用视频或硬件后另行确认。
