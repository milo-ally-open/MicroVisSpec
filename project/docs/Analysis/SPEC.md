# 消防通道占用告警平台技术规格（草案）

> 状态：提案草稿；依赖 [PRD 0.5](PRD.md) 中待确认的全栈联调阶段
> 最近更新：2026-10-03

## 1. 概述与 PRD 对应关系

本规格为“单点位、模拟事件、后端持久化、网页通过接口读取与更新”提出候选技术边界。PRD 范围获团队确认前，本文接口和字段均为讨论稿，不应视为已经批准的稳定契约。

| PRD 范围 | 技术落点 | 本提案处置 |
|---|---|---|
| 模拟告警生成 | Web 模拟入口调用创建事件接口，事件标记 `source=simulated` | 纳入提案 |
| 告警列表与详情 | 查询告警 API，返回事件字段与证据引用 | 纳入提案 |
| 更新处置状态 | 状态更新 API；服务端检查允许的状态流转 | 纳入提案 |
| 单个模拟点位 | 固定初始化一个演示点位，暂不建设完整设备管理 | 纳入提案 |
| 模拟截图 | 使用静态示例图引用并保留模拟标记 | 纳入提案；不做上传 |
| 实时视频与真实 YOLO 告警 | 摄像头/RTSP、边缘推理及占用持续时间逻辑 | 本阶段不实现 |
| 手机推送、用户权限、分析大屏、MCP | 后续独立需求与规格 | 本阶段不实现 |

## 2. 架构与系统边界

```text
Web 告警界面 ──HTTP/JSON──> 告警 API/应用服务 ──> 持久化存储
                                  ↑
                         当前：模拟事件入口
                         未来：YOLO/边缘事件适配器
```

- 本机工作区有浏览器原型；本次文档交接不包含其代码。API、服务和持久化存储尚未实现。
- 建议全栈演示阶段使用一个后端应用和一个持久化存储，不建设微服务集群。
- API 风格暂提议 HTTP/JSON REST：适用于当前浏览器调用，也给未来算法生产者提供独立接入边界；直接由网页访问数据库会耦合客户端和存储，并破坏跨会话共享，因此不采用。
- 后端框架、数据库、部署方式和依赖版本均待 Research 后确定。本草案不指定技术栈。

| 模块 | 职责 | 责任人 | 状态 |
|---|---|---|---|
| Web 告警客户端 | 告警列表、详情、状态操作、模拟事件触发；用 API 作为共享数据来源 | 用户 | 有本地原型；API 接入未实现 |
| 模拟事件入口 | 生成标记为模拟来源的事件 | 用户 | 待实现 |
| 告警应用服务 | 校验输入、生成 ID、默认状态、查询事件、限制状态流转 | 用户 | 待实现 |
| 持久化层 | 保存告警字段和状态 | 用户 | 存储类型待定 |
| 图片与数据集 | 采集/整理图片、预处理、标注与数据集划分 | 队友 | 依用户提供的分工说明 |
| YOLO 模型链路 | 模型选型、设计、训练、导出/转换、评估、验证、剪枝和部署推理 | 队友 | 具体模型交付物待双方确认 |
| 模型到平台的事件接入 | 传递模型推理结果和证据，交由告警服务生成业务事件 | 双方 | 字段、传输形式和服务边界待定 |

## 4. 接口契约（候选）

接口前缀建议为 `/api/v1`。该版本路径和 REST 形式都待团队确认。

### 创建事件

`POST /api/v1/events`

请求示例（模拟来源）：

```json
{
  "eventType": "fire_lane_occupied",
  "pointId": "demo-south-gate",
  "deviceId": "demo-camera-01",
  "detectedAt": "2026-10-03T10:00:00+08:00",
  "durationSeconds": 0,
  "confidence": null,
  "evidenceRef": "assets/simulated-evidence.svg",
  "source": "simulated"
}
```

建议由服务端生成 `id`、`createdAt`、`updatedAt`，并将初始 `status` 设为 `pending`。模型端将来的 `confidence`、`durationSeconds`、`evidenceRef` 语义和可空规则需与算法负责人确认。

### 查询事件

- `GET /api/v1/events?status=pending`：返回按发生时间倒序排列的事件列表；过滤参数可选。
- `GET /api/v1/events/{eventId}`：返回单条事件；不存在时返回 `404`。

### 更新状态

`PATCH /api/v1/events/{eventId}/status`

请求示例：

```json
{ "status": "processing" }
```

候选状态与流转：

| 当前状态 | 允许的下一状态 |
|---|---|
| `pending` | `processing`、`resolved`、`false_alarm` |
| `processing` | `resolved`、`false_alarm` |
| `resolved`、`false_alarm` | 无；终态 |

未知状态或非法流转建议返回 `400`；事件不存在返回 `404`。最终错误结构待定。

## 5. 数据模型（候选）

| 字段 | 类型/格式 | 含义 |
|---|---|---|
| `id` | string | 服务端生成的唯一事件编号 |
| `eventType` | string | 事件类型；当前候选值 `fire_lane_occupied` |
| `pointId` | string | 点位编号；当前仅演示点位 |
| `deviceId` | string | 设备编号；模拟设备标识 |
| `detectedAt` | ISO 8601 时间 | 事件发生/检测时间 |
| `durationSeconds` | number | 连续占用时长；模拟阶段可为 0 |
| `confidence` | number 或 null | 模型置信度；模拟阶段为空 |
| `evidenceRef` | string 或 null | 证据图引用；当前指向静态示例图 |
| `source` | enum | `simulated`；未来候选 `edge` |
| `status` | enum | `pending`、`processing`、`resolved`、`false_alarm` |
| `createdAt`、`updatedAt` | ISO 8601 时间 | 服务端记录创建与更新时间 |

上述字段不包含人员身份或账号权限；处置人和处理备注不属于当前提案范围。

## 6. 非功能要求

- 页面必须持续显示模拟/真实来源标记；当前版本所有生成事件均为模拟数据。
- 单个演示点位、低并发本地演示；具体性能、可用性和容量指标待部署目标明确后定义。
- 同一后端下，事件创建和状态修改应持久化，刷新或另一个浏览器会话可读到更新。
- 不将任何模型权重、令牌或本机路径作为 API 配置提交到仓库；模型权重文件不得加入、提交或推送到代码仓库。

## 7. 依赖

- PRD 0.5 的前后端联调范围获得团队确认。
- 团队确定后端语言/运行环境、存储方式和开发启动方式。
- 队友负责图片/算法链路；用户负责平台前后端与系统集成。双方需确认模型推理结果的类别语义、事件字段和证据图传递约定。

## 8. 部署与运维

- 本地开发启动命令、环境变量、数据库迁移方式待选型后补充。
- 模拟版不得使用真实设备凭据或宣称为生产告警系统。
- 模型权重不得上传到代码仓库。当前模型权重留在本机；任何仓库外共享渠道都需单独确认。

## 9. 风险与被否决方案

- **方案：多个微服务分别实现 device、media、user、alert。** 当前只有单点模拟流程，没有独立扩缩容或团队边界证据；建议先做一个告警应用，避免增加本阶段部署和联调成本。
- **方案：前端直接保存共享数据。** `localStorage` 只对当前浏览器可见，无法满足跨会话共享；因此全栈提案采用后端 API 作为共享数据边界。
- 生产级认证、权限、审计、上传、安全和性能设计仍未定义，当前草案不能用于生产部署。

## 10. 待确认
