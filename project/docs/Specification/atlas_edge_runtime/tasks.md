# Atlas 200I DK A2 边缘运行时与云边代理实施任务

> 关联合同：[spec.md](spec.md)；设计：[design.md](design.md)。本清单记录计划和证据，不代表当前已有实现。

## 任务清单

- [ ] **T-01 Atlas 构建与运行依赖基线** — 核对 CANN/OpenCV/FFmpeg/SQLite、aarch64 TLS MQTT client、systemd 权限；锁定可复现交叉/板端构建方案和包版本；覆盖 REQ-01、REQ-02、REQ-03 / AC-01.1、AC-02.2、AC-03.1；依赖：无。
- [ ] **T-02 agent 设备身份与配置心跳** — 消费激活响应的 broker 地址、原样 `client_id`、独立凭据和 CA；发布符合 device-service 合同的设备/NPU/模型/摄像头/流/MQTT/outbox 状态心跳；处理网页发起的 HTTPS 激活/续期租期轮询和到期暂停/恢复；覆盖 topic ACL、配置版本/回执与状态 API/MQTT；覆盖 REQ-01、REQ-02 / AC-01.1、AC-01.2、AC-01.3、AC-01.4、AC-01.5、AC-01.6、AC-02.1、AC-02.2、AC-02.3、AC-02.5；依赖：T-01、device-service。
- [ ] **T-03 多模型配置、模型目录和推理进程管理** — 参照 AX650 plugin/manager 分层，在 `config/models.json` 定义模型与支持能力、`streams_config.json` 定义逐流 model_id 绑定、`alarm_rules.json` 定义数据驱动且默认关闭的告警；实现 profile 与活动 manifest 的类别/SoC/格式/尺寸匹配、通用 catalog 不固化课堂类别、模型按 model_id 哈希校验和 staging 原子激活、`active/{model_id}` 独立回滚、最大加载数限制、NPU 状态与 Unix socket；插件、model_id、流/规则/manifest 使用 `model_` 前缀和领域名、任务类型组成的统一命名（task 为 detection/segmentation/classification），插件类和 `IAIModel::name()` 与 model_id 一致，插件 ABI 版本与 runtime 匹配，算法键和模型族保持各自语义；媒体接口与实现按 `include/media/*.hpp` ↔ `src/media/*.cpp` 同基名配对；`include/common/core.hpp` ↔ `src/common/core.cpp`、`include/common/config.hpp` ↔ `src/common/config.cpp` 同基名配对；Atlas 实现使用 AscendCL/DVPP，不复用 AX650 SDK；覆盖 REQ-03 / AC-03.1、AC-03.2、AC-03.3、AC-03.4、AC-03.5、AC-03.6、AC-03.7、AC-03.8、AC-03.9、AC-03.10，REQ-02 / AC-02.4；依赖：T-01。课堂检测 T-01/T-02 消费此任务提供的 profile/活动模型接口，不构成反向依赖。
- [ ] **T-04 SQLite 事件 outbox 与 ACK 恢复** — 实现稳定 ID、QoS1、accepted/duplicate 完成、rejected quarantine、重连/重启/磁盘告警；覆盖 REQ-04 / AC-04.1、AC-04.2、AC-04.3、AC-04.4、AC-04.5、AC-04.6；依赖：T-02、event-service。
- [ ] **T-05 媒体及证据云边接入** — 将授权 live 输入、处理后预览及其尺寸/帧率/码率、来源断流状态和规则触发截图接入 media/event 服务；FFmpeg 打开/探测/读取均有界，断流经退避重连；runtime 使用 GStreamer RTSP Server/AppSrc 按 stream 配置提供无需认证的 RTSP 输出，media-service 通过单一可达 `rtsp_url` 将其登记为 `sourceOnDemand` 来源；验证匿名拉流、客户端断开不阻塞推理、来源重连、真实相机链路和端到端播放；覆盖 REQ-05 / AC-05.1–05.4；依赖：T-03/T-04、MediaMTX。已在 Atlas 合成 UDP 输入上验证超时与两轮恢复，RTSP/MediaMTX 发布和真实相机链路仍未完成。
- [ ] **T-06 服务化部署与运维恢复** — systemd 单元、非特权运行、配置/密钥及必需 CANN 环境文件注入、动态库解析、最小设备组和 udev RGN 权限、升级/回滚、日志与健康探针；配合 device-service 网页固定地址 SSH 首次引导、指纹确认和一次性凭据兑换；覆盖 REQ-01、REQ-02、REQ-03、REQ-04、REQ-06 / AC-01.7、AC-02.1、AC-02.2、AC-03.2、AC-04.5、AC-04.6、AC-06.1、AC-06.2、AC-06.3、AC-06.4；依赖：T-01–T-05。
- [ ] **T-07 边缘服务内集成测试** — 使用隔离的 MQTT、device/event/media stub 与临时 SQLite/模型 fixture，覆盖身份和 ACL、Atlas 状态 payload 合同、配置乱序、两模型 JSON profile 隔离、按 model_id 激活/回滚互不影响、加载上限、模型/插件命名校验、插件缺少/错配 ABI 版本时拒绝加载、确定性 YOLO 推理后处理、ACK 丢失/重复/永久拒绝、磁盘告警、媒体断连及服务重启；覆盖 REQ-01、REQ-02、REQ-03、REQ-04、REQ-05 / AC-01.1、AC-01.2、AC-01.3、AC-02.1、AC-02.2、AC-02.3、AC-02.4、AC-02.5、AC-03.1、AC-03.2、AC-03.3、AC-03.4、AC-03.5、AC-03.6、AC-03.7、AC-03.8、AC-03.9、AC-03.10、AC-04.1、AC-04.2、AC-04.3、AC-04.4、AC-04.5、AC-04.6、AC-05.1、AC-05.2、AC-05.3、AC-05.4；依赖 T-01–T-06。
- [ ] **T-08 Atlas 云边链路实机验收与规格回写** — 在目标板记录激活/撤销、云端配置 ACK、断网缓存恢复、媒体接入和资源数据；模型推理性能/类别精度由课堂检测 T-07 验收；覆盖 REQ-01、REQ-02、REQ-04、REQ-05 / AC-01.1、AC-01.2、AC-01.3、AC-02.1、AC-02.2、AC-02.3、AC-04.1、AC-04.2、AC-04.3、AC-04.4、AC-04.5、AC-04.6、AC-05.1、AC-05.2、AC-05.3、AC-05.4；依赖 T-07、真实设备和模型包。
