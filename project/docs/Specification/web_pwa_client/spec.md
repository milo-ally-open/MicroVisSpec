# Web 与 PWA 客户端行为规格

> 关联提案：[proposal.md](proposal.md)；全局合同：[总 SPEC](../../Analysis/SPEC.md)。

## 范围和术语

覆盖已登录平台用户的桌面 Web 与手机 PWA，面向多行业的边缘设备、算法、视频和事件管理。平台级导航、品牌和引导文案不绑定单一行业；当前部署的具体算法可展示其真实类别与规则。**异常事件**只来自边缘已启用且命中规则的类别；普通检测不进入告警列表或推送。

## 需求与验收条件

### REQ-06：工作台视觉与响应式可用性

- **AC-06.1** Given 1440/1024px 桌面或平板及 390/360px 窄屏，When 浏览登录、注册、概览、设备、事件、统计和设置，Then 导航、标题、卡片和表单采用一致视觉层级，页面无横向溢出；窄屏优先事件与设备流程。
- **AC-06.2** Given 键盘或触屏用户，When 操作导航、表单和按钮，Then 焦点可见、纯图标按钮有名称，装饰 SVG 不占用朗读内容，主要控件可清晰点击。
- **AC-06.3** Given 进入概览或切换统计范围，When 显示日期、问候和事件数量标题，Then 使用上海时区的当前日期/时段及已选范围，数据仍来自既有服务，不伪造在线状态或统计。
- **AC-06.4** Given 登录表单密码已填写，When 点击显示/隐藏密码，Then 仅切换当前输入框类型并保留内容，使用原有登录接口和会话合同。
- **AC-06.5** Given 用户在桌面或手机 Web/PWA 查看工作台、登录页或注册页，When 页面展示品牌区，Then 使用仓库项目 Logo，并显示完整座右铭“边缘智能识别，云端统一处置”；平台品牌文案不绑定单一行业。
- **AC-06.6** Given 用户查看产品工作台，When 在桌面或手机打开任一业务页面、认证页、离线提示或更新提示，Then 使用 `readme/yunshao-exhibit.html` 的暖纸色、墨色与森林绿视觉基调和清晰标题层级；不加载远程字体，且不改变现有页面结构、路由、API 或交互行为。

### REQ-07：局域网部署入口

**需求**：部署方可让受信任的团队 Wi‑Fi 用户通过 HTTPS 使用 Web/PWA，同时保留 Atlas 设备经独立网络接口访问激活入口的能力；其他后端与管理端口不对用户网段发布。

- **AC-07.1** Given 用户位于部署方允许的 Wi‑Fi 网段且客户端信任服务端证书，When 打开配置的 HTTPS 地址，Then 静态工作台、同源 API 与媒体请求使用同一 Origin；HTTP 入口跳转到配置的 HTTPS 主机端口。
- **AC-07.2** Given Atlas 通过独立直连接口访问部署主机，When 执行设备激活并连接 MQTT，Then Web 激活入口仍可经 Atlas 地址访问，MQTT 继续绑定 Atlas 接口；数据库、服务 API 与 MediaMTX 管理接口不向 Wi‑Fi 客户端发布。
- **AC-07.3** Given Wi‑Fi/Atlas 网段的防火墙规则已配置，When 外部网段尝试访问，Then Web HTTP/HTTPS 仅允许规定的客户端网段；部署说明指出当前 Wi‑Fi 网段 `172.50.53.0/24` 不属于 RFC 1918，须确认边界 ACL 阻止非预期入站访问。

### REQ-01：账号安全与路由

**需求**：前端通过同源 API 管理登录态，受保护页面不得在未鉴权时读取账号数据。

**验收条件**

- **AC-01.1** Given 未登录用户访问受保护路由，When 前端发现 401，Then 清理内存中的个人数据并跳转登录，登录后返回安全的站内目标路由。
- **AC-01.2** Given Cookie 写请求，When 客户端调用 API，Then 发送服务器提供的 CSRF token；登出/改密清除状态并处理服务端撤销。
- **AC-01.3** Given API 返回 403/404/409/410/422/429/503，When 呈现结果，Then 按全局错误合同反馈，避免显示其他账号对象是否存在。
- **AC-01.4** Given 登录接口返回 401，When 用户提交用户名/密码被拒绝，Then 显示“用户名或密码不正确，请重新输入”，不触发已有会话失效事件；受保护接口的 401 仍执行 AC-01.1。

**验证方式**：组件/API 集成测试及浏览器流程验证。

### REQ-02：设备与算法工作台

**需求**：用户应能登记和查看边缘设备、摄像头、算法状态及授权实时视频，并显式配置已部署算法支持的告警规则。

**验收条件**

- **AC-02.1** Given 设备列表、详情、摄像头和运行状态 API 返回，When 用户查看设备页，Then 设备在线、视频连接、模型/NPU运行、配置应用状态彼此区分。
- **AC-02.2** Given 授权视频可播放，When 用户查看监控，Then 显示有权限的处理后视频、地点和连接状态；WebRTC 失败时按服务提供的 HLS 回退 URL 呈现。
- **AC-02.3** Given 初始/新模型配置，When 用户打开规则页，Then 举手、阅读、书写规则均为关闭；启用某类必须填写有效置信度、持续条件和事件等级，提交后显示期望版本与设备实报版本。
- **AC-02.4** Given 推送设备/模型/API 状态不可用，When 页面加载，Then 显示明确错误或待连接状态，不渲染假实时画面。
- **AC-02.5** Given 当前账号拥有已登记摄像头，When 用户在设备详情配置视频来源，Then 页面回显已保存的 `rtsp_url`，仅提供一个 RTSP 地址输入框并提交到 media-service；保存后显示服务端配置状态，拒绝非 RTSP/无 host/带 userinfo 的地址；界面和请求不含来源用户名或密码字段。其他账号不能读写该摄像头来源。
- **AC-02.6** Given 当前账号拥有待激活设备，When 设备尚无可信 agent 身份，Then 用户可从详情页启动首次 SSH 接入并选定授权期限；已有可信身份的有效或到期设备仍可直接网页激活/续期。期限可为无限期或正整数自定义时长（分钟、小时、天），请求以 `duration_seconds` 传递；超出范围时前端阻止提交并说明原因。
- **AC-02.7** Given 设备激活期限已结束，When 用户打开设备列表或详情，Then 状态显示“授权已到期”且可在网页续期；页面轮询请求状态，先显示设备同步中，确认后展示新的服务器到期时间，无限期设备显示无到期时间。网页不得展示激活票据、命令行或 MQTT 密码。
- **AC-02.8** Given 已部署设备 agent 在线并持有可信设备身份，When 用户提交网页激活/续期请求，Then agent 在后台通过经 TLS 验证的 HTTPS 轮询领取新凭据并重启，页面在 agent 确认保存新凭据前显示同步中，用户无需登录 Atlas 或打开命令行；响应丢失时 agent 可自动重领相同凭据。首次接入由设备所有者在网页输入管理员提供的 SSH 账号凭据后自动完成。

**验证方式**：设备与媒体 API 集成测试；实机媒体联调。

### REQ-08：网页设备首次接入向导

**需求**：园区用户可在设备详情页使用管理员提供的 SSH 登录信息完成 Atlas agent 部署和可信激活；初始化与后续激活均不要求用户操作 Atlas 终端。

- **AC-08.1** Given 待激活设备，When 用户点击首次接入，Then 页面只针对设备已登记 IP 请求 SSH 指纹，首次展示 SHA-256 指纹并要求用户确认；不提供主机/IP、端口或命令输入框。
- **AC-08.2** Given 用户确认指纹并提交 SSH 用户名/密码，When device-service 执行接入任务，Then 密码仅通过当前 HTTPS 请求传输且不进入浏览器持久存储、服务数据库、任务记录或日志；页面清空密码字段。
- **AC-08.3** Given 有效的 SSH 凭据及可用 Atlas CANN 环境，When 后端安装 agent 并兑换所选期限的激活票据，Then UI 展示安全阶段与设备在线结果；不显示激活票据、MQTT 密码或原始 SSH 输出。
- **AC-08.4** Given SSH 凭据错误、指纹变化、网络不通、CANN 缺失或构建失败，When 任务结束，Then UI 给出可操作且不泄密的错误说明，任务允许重试并在板端清理临时文件。
- **AC-08.5** Given 设备首次接入成功，When 接入任务完成，Then 页面显示设备已接入并激活；后续访问设备详情只显示网页续期流程，不再索要 SSH 密码。用户刷新或重新进入页面时，未完成任务进度由服务端恢复。

**验证方式**：Web/API 类型与生产构建检查；隔离环境模拟 SSH 主机认证、账号越权、任务状态与敏感字段脱敏；Atlas 200I DK A2 实机验收构建、激活、心跳及失败重试。

### REQ-03：事件查询与处置

**需求**：事件页面仅呈现服务端已生成且归属当前账号的异常事件，支持筛选、详情、证据和处置。

**验收条件**

- **AC-03.1** Given 各筛选条件，When 用户查询，Then 使用稳定游标分页并保留 URL 可分享的非敏感筛选状态。
- **AC-03.2** Given 事件详情，When 证据待传、缺失或已过期，Then 分别显示待上传、不可用或已过期，不使用公开文件 URL。
- **AC-03.3** Given 合法/非法或并发处置，When 用户提交状态与结果，Then 展示服务器接受的最新状态，冲突时刷新；终态记录要求结果。
- **AC-03.4** Given 页面收到普通模型检测而无已命中规则事件，When 用户查看告警列表，Then 不将普通检测虚构成告警。

**验证方式**：event-service API 集成测试和 UI 流程测试。

### REQ-04：统计和通知

**需求**：统计只反映生成的异常事件，PWA 用户可选择启用 Push 并从通知安全跳转。

**验收条件**

- **AC-04.1** Given `today`、`7d`、`30d` 统计，When 展示卡片/图表，Then 明确范围、更新时间和空结果；设备与事件 `as_of` 分开显示。
- **AC-04.2** Given 用户未授权、拒绝或浏览器不支持 Push，When 页面加载，Then 提供清晰状态且不阻断事件查询。
- **AC-04.3** Given 有效 Push 通知，When 用户点击，Then 打开站内事件详情并由登录态重新鉴权；通知不含截图或个人识别信息。

**验证方式**：前端统计/API 集成测试、service worker 测试、支持浏览器手工验收。

### REQ-05：PWA 生命周期和数据边界

**需求**：PWA 离线仅提供应用壳，不缓存账号、API、课堂媒体或截图；安装和更新不丢失服务端状态。

**验收条件**

- **AC-05.1** Given 应用离线启动，When service worker 返回缓存资源，Then 仅显示静态壳及离线提示，隐藏过期个人数据。
- **AC-05.2** Given 新版本 PWA，When 检测到更新，Then 提示用户安全刷新；登录、配置和处置最终状态从服务端重载。

**验证方式**：service worker/API cache 审查与离线浏览器测试。

## 不变项与兼容要求

- API 同源 `/api/v1`；所有对象授权依赖后端，不以隐藏按钮代替。
- Cookie、CSRF、错误体、状态码、snake_case API 与 RFC 3339 时间遵守总 SPEC。
- 只有启用规则创建的服务端事件会显示在告警、统计与推送中。
- 桌面实时监控布局不作为手机 PWA 首屏；移动端优先设备概况、事件和处置。

## 数据处理和保留

- Service worker 只缓存 manifest、静态资源与应用壳；API 响应、摄像头视频、截图、订阅 endpoint 均不缓存。
- 浏览器仅持有安全会话 Cookie；Push payload 只含必要事件定位字段。
- 事件截图通过账号授权 API 加载，并遵守成功上传 24 小时后过期合同。

## 明确不做

- 消防通道首发页面、原生移动应用、MCP 面板、离线历史事件。
- 身份识别、个人评分或注意力分析；普通检测历史记录页面。

## 假设与未决问题

- 页面视觉依据为仓库内 `readme/yunshao-exhibit.html`；展品页的市场介绍布局不复制到工作台，视觉调整不改变交互合同。
- `[待核验]` 当前团队 Wi‑Fi `172.50.53.0/24` 的入口 ACL 和客户端隔离状态；该地址段非 RFC 1918，需由部署网络确认仅向团队开放并为主机保留地址。
- `[待核验]` 目标浏览器与园区网络对 WebRTC、HLS、Push 的真实支持。
