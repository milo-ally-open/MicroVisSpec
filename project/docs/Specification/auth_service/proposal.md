# auth-service 范围提案

> 状态：基线；实现状态以代码、部署记录和验收证据为准。
> 关联文档：[总目录](../README.md)、[产品需求](../../Analysis/PRD.md)、[总技术规格](../../Analysis/SPEC.md)、[系统架构](../../Design/STRUCTURE.md)、[服务规格](spec.md)。

## 目标

统一管理 PC/mobile/admin 账号身份、密码、浏览器会话、工作空间成员/邀请/设备能力授权、受控管理员 bootstrap 和账号状态变更。

## 范围

自助 PC 注册、管理员受控创建 PC、邀请绑定 mobile、登录/本人信息/退出/改密、成员和邀请维护、内部 capability 判定、管理员账号/健康/审计接口及会话撤销事件。

## 边界

密码找回和客户设备/事件/媒体/Push 业务数据；这些数据仍归各业务服务管理。平台管理员不绕过 workspace/device capability，也没有部署修改或服务重启权限。

实现状态见本服务 `tasks.md` 和[三类用户与工作空间授权规格](../multi_user_workspace_access/)；现有源码已实现多用户授权垂直切片，但迁移、撤权传播和目标环境验收仍未完成，不能据此宣称功能完整。

## 文档关系

本提案记录长期范围；`spec.md` 是详细需求与验收合同，`design.md` 汇总技术边界，`tasks.md` 记录核验与实施进度。实现状态必须由代码、运行结果和验收证据判断，不能由本文件状态推断。
