# event-service 范围提案

> 状态：基线；实现状态以代码、部署记录和验收证据为准。
> 关联文档：[总目录](../README.md)、[产品需求](../../Analysis/PRD.md)、[总技术规格](../../Analysis/SPEC.md)、[系统架构](../../Design/STRUCTURE.md)、[服务规格](spec.md)。

## 目标

拥有通用事件、证据、处置、账号内查询统计和通知 outbox。

## 范围

MQTT 接入/应用 ACK、证据生命周期、查询处置统计及 event.created。

## 边界

设备资产主数据、推送投递及算法检测逻辑。

当前查询合同按账号隔离，代表单账号基线。三类用户目标下，事件及证据按 `workspace_id` 作为租户资源归属；查询、截图和处置必须再校验实际操作者的设备 grant，并记录真实 actor，不能把 workspace 所有者当作成员操作者。跨服务共享合同见[三类用户与工作空间授权规格](../multi_user_workspace_access/)。

## 文档关系

本提案记录长期范围；`spec.md` 是详细需求与验收合同，`design.md` 汇总技术边界，`tasks.md` 记录核验与实施进度。实现状态必须由代码、运行结果和验收证据判断，不能由本文件状态推断。
