# 移动端与 PWA 任务书

> 状态：草案，待团队确认；不代表当前阶段已获批准
> 依据：[PRD 0.5](../Analysis/PRD.md)、[平台技术规格草案](../Analysis/SPEC.md)
> 范围：现有模拟告警网页的移动端使用；可安装 PWA 能力须另行确认

## 1. 目标

让值班人员能在手机浏览器中查看和处置平台告警。优先复用现有告警原型和统一后端 API，不重做业务流程，也不把 PWA 扩成推送、离线处置或手机客户端项目。

## 2. 当前基线

- 本机工作区原型位于 `project/src/clients/web/alert-prototype/`，已有告警列表、详情、状态筛选、模拟告警创建和处置状态更新；该代码不包含在本次文档交接中，开始实现前需先共享原型或以实际分支代码重新确认基线。
- 页面已有视口设置和响应式 CSS 断点，因此开发前应先在目标手机宽度检查实际缺口；只修改未满足本任务验收条件的部分。
- 事件目前保存在当前浏览器的 `localStorage`；后端 API 和共享持久化尚未实现。
- 页面明确标记模拟事件和示意画面；此提示必须保留。

## 3. 状态与前置条件

本任务书当前仅供团队讨论。开始完整联调前需满足：

1. 团队确认 PRD 中的单点位模拟告警全栈联调阶段。
2. 后端技术选型与告警 API 契约已在 Research/SPEC 中确认并实现可调用版本。
3. 团队确认本任务的“PWA”是否只指移动端网页体验，还是还要求可安装应用。

在前置条件完成前，可以审查现有手机布局，但不能把后端共享数据验收标记为通过。

## 4. 本阶段范围

### 必须完成：移动端网页体验

- 在手机窄屏上查看告警列表、筛选状态、打开详情、生成模拟告警和更新处置状态。
- 页面使用与桌面端相同的告警 API 和事件数据；不为手机单独保存另一套业务数据。
- 刷新页面和从另一浏览器会话访问时，展示后端保存的最新事件和状态。
- 保留模拟来源、示意截图和非真实检测结果的清晰提示。
- 请求失败时给出可理解的提示，不静默地把后端不可用伪装成本地保存成功。

### 可选范围：可安装 PWA（待团队确认）

只有团队明确选择后，才增加应用清单、图标和安装体验。Service Worker 仅在团队另行确认需要缓存或离线行为时再评估，不作为安装能力的默认前提。选定前先保持普通响应式网页，不引入安装或缓存逻辑。

## 5. 不在本任务范围

- 手机推送通知、通知权限申请和后台推送服务。
- 离线创建或修改告警、离线队列和多端冲突处理。
- 真实摄像头画面、模型推理、RTSP 播放及真实告警。
- 登录、完整用户权限、多租户、多点位及生产级安全设计。
- 重写现有前端框架或另建一套仅供手机使用的客户端。

若后续启用 Service Worker，不得把缓存的告警 API 数据呈现为最新数据；缓存范围和离线行为需另立规格。

## 6. 执行步骤

1. 检查现有原型在手机尺寸下的布局和交互，只记录可复现的问题。
2. 先按验收标准修复必要的响应式布局、触控操作和内容溢出问题。
3. 在后端 API 可用后，将原型的读取、创建和状态更新接到统一 API，移除这些业务操作对 `localStorage` 的依赖。
4. 与后端联调并验证刷新、另一浏览器会话及请求失败时的表现。
5. 若团队批准可安装 PWA，再单独完成可安装能力并补充相应验收记录。

## 7. 验收标准

- 在 320 CSS 像素宽度及常见手机视口下，主要页面无横向溢出；告警列表、详情、筛选和处置按钮可操作。
- 创建模拟告警后，刷新页面仍可从后端读取到该记录；更新状态后重新读取显示新状态。
- 同一后端的另一浏览器会话能看到相同记录和状态。
- API 请求失败时显示失败状态，且不声称操作已保存。
- 所有演示事件仍清楚标记为模拟数据，静态示例图仍标记为非真实监控画面。
- 若批准可安装 PWA，另行确认安装目标浏览器和运行环境后再验收；安装能力不能替代上述业务验收。

## 8. 责任与未决事项

- 负责人：用户（平台前端、后端和系统集成）。
- 依赖：后端技术与部署方式、API 字段及跨浏览器可访问的演示环境待团队确认。
- 待决：团队是否要求可安装 PWA；若要求，目标手机系统/浏览器是什么。
- 任何模型权重、令牌和本机路径不得加入、提交或推送到代码仓库。

## 9. 完成定义

只有团队确认的范围、验收项和依赖均完成，并记录未覆盖项后，本任务才算完成。若只完成响应式页面，应报告为“移动端适配完成”，不能称为完整 PWA。
